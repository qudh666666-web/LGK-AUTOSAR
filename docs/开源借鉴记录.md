# 开源实现借鉴：2026-09-13

目标是让失败请求一次返回可行动的信息，减少 Agent 重查和输出量。

## 采用的思路

参考 [claude-autosar 的 bsw_write_ops.py](https://github.com/jasontaotao/claude-autosar/blob/main/packages/autoc/src/claude_autosar/cli/mcp_tools/bsw_write_ops.py)
中结构化 field/param_index 错误及简短校验报告的设计；
[包元数据](https://github.com/jasontaotao/claude-autosar/blob/main/packages/autoc/pyproject.toml)
声明 MIT。这里只借鉴接口思路，Rust 实现与测试独立编写，没有复制其源代码、注释、
测试数据或引入 Python/MCP 依赖。上游 main 会变化，以上是本日审阅入口。

LGK-Vector v0.3.9 落地范围：

- MODULE_REQUIRED / MODULE_NOT_FOUND：字段定位及当前工程候选；最多 8 个，
  不执行自动纠错，保留 module_name 与大小写兼容。候选来自已加载 DPA，
  不追加 SIP 扫描；候选提示是结合本工具模块命名需求的本地设计。
- DELIVERY_VERIFICATION_FAILED：默认严格模式的失败响应直接包含不一致、
  文件缺失、缺少/禁用文本及原请求 check_index（从 0 开始），无需先重跑
  enforce:false。最多 8 个失败项，每类文本最多 8 条，并返回总数/截断标志。
- 保留非零退出码和现有 CLI `Error:` / 包装器异常外层；JSON 位于错误详情中，
  不是成功 stdout。成功格式不变。其他错误尚未统一成这些结构化错误码。

## 本轮未引入

[autosar-data-abstraction](https://github.com/DanielT/autosar-data-abstraction)
提供 ECUC 模型接口，项目有 MIT/Apache-2.0 许可；它适合将来的模型操作评估。
本轮两个诊断改进不需要替换 XML 数据模型，因此没有集成该 crate 或复制实现。

claude-autosar 的 DaVinci 适配器另有命令约定及超时配置，本轮没有在本机验证其
命令兼容性，不据 README 功能数量替换 LGK-Vector 的已用执行链。也没有引入
跨工具适配、会话数据库、自动模板写入或新一轮 Agent 审批。

验证记录见 CHANGELOG v0.3.9。没有测量真实 LLM token；节省的是明确可消除的
重复诊断请求，不能把测试数量或单次耗时当作 token 基准。
