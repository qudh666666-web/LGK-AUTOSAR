# LGK-Vector 全局共享接入与源码维护

## 1. 最终结构

整台电脑只保留一份 LGK-Vector 源码和程序：

```text
D:\Tools\LGK-Vector\
├─ SKILL.md
├─ Cargo.toml / Cargo.lock
├─ src\
├─ scripts\
├─ tests\
├─ docs\
├─ CHANGELOG.md
└─ target\release\lgk-vector*.exe
```

各 AUTOSAR 工程不复制 `Vector\LGK-Vector`，只在自己的 DaVinci Cfg 目录保存一份工程配置：

```text
D:\Project\ProjectA\Proj_Config\Bsw_Config\Cfg\lgk-vector.json
D:\Project\ProjectB\Cfg\lgk-vector.json
```

这样工具源码、Skill、程序和更新记录始终只有一个版本；工程 A 中发现并修复的问题，工程 B 下一次调用时直接使用修复后的中央版本。

## 2. 让 Codex 从任何工程发现它

Codex 需要在用户 skills 目录看到 `lgk-vector`。不要复制源码，使用 Windows 目录链接把入口指向 D 盘：

```powershell
& "D:\Tools\LGK-Vector\scripts\Install-LGKVectorSkill.ps1"
```

默认建立：

```text
C:\Users\<用户名>\.codex\skills\lgk-vector
    → D:\Tools\LGK-Vector
```

箭头左侧只是目录链接，不是第二份源码。以后无论 Codex 当前打开哪个工程，触发 `$lgk-vector` 后读到的都是 D 盘同一份 `SKILL.md`、Rust 源码和 Git 历史。

如果 skills 位置不同，可以明确指定：

```powershell
& "D:\Tools\LGK-Vector\scripts\Install-LGKVectorSkill.ps1" `
  -SkillPath "C:\Users\UserName\.codex\skills\lgk-vector"
```

脚本发现目标位置已经存在普通文件夹时会停止，不会擅自覆盖。先检查旧目录是否有独有修改，再决定迁移。

## 3. 给每个 AUTOSAR 工程配置

在该工程实际的 DaVinci Cfg 目录创建 `lgk-vector.json`：

```json
{
  "project_path": "D:\\Project\\ProjectA\\Proj_Config\\Bsw_Config\\Cfg",
  "tool_path": "D:\\Vector\\SIP"
}
```

`project_path` 必须等于 JSON 所在目录。`tool_path` 指向本机可用且与该工程匹配的 Vector SIP/工具环境。

如果目录中存在多个 `.dpa`，或者工具目录中存在多个 `DVCfgCmd.exe`，再增加：

```json
{
  "project_path": "D:\\Project\\ProjectA\\Proj_Config\\Bsw_Config\\Cfg",
  "tool_path": "D:\\Vector\\SIP",
  "project_file": "D:\\Project\\ProjectA\\Proj_Config\\Bsw_Config\\Cfg\\Vehicle.dpa",
  "davinci_command_path": "D:\\Vector\\DaVinci\\Exec\\DVCfgCmd.exe"
}
```

旧工程的 `LGK_project_path`、`LGK_tool_path` 继续兼容；新工程统一使用小写字段。

## 4. 从任意工程调用

先做预检，不启动 host 或 DaVinci：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Project\ProjectA\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"find_module","module":"Com"}' `
  -ValidateOnly
```

只读查看 COM Signal：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Project\ProjectA\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"inspect_ecuc_containers","module":"Com","container":"ComSignal","short_name_regex":"^VehicleSpeed$","params":["ComBitPosition","ComBitSize"]}'
```

会话结束：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Project\ProjectA\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"shutdown_host"}'
```

ECUC 配置修改属于目标 AUTOSAR 工程；DaVinci 生成的 C/H/LSL 是该配置的输出。两者都在目标工程中检查和提交。LGK-Vector 自身的 Rust、Skill 和脚本只在中央源码仓库提交。

## 5. 从任何工程更新工具

当实际工程暴露出工具问题时：

1. 触发 `$lgk-vector`，Codex 会通过目录链接进入 D 盘中央源码。
2. 在 `CHANGELOG.md` 确认当前版本和限制。
3. 查看相关源码：本地操作位于 `src\ops`，host 和 DaVinci 协议位于 `src\app`、`src\daemon`，调用器位于 `scripts`。
4. 使用虚构或可公开的最小测试夹具复现，不要把客户 DPA、ARXML、DBC 或 SIP 复制进工具仓库。
5. 修改源码并补测试，运行：

```powershell
cargo test --all-targets --locked
cargo build --release --locked
```

6. 更新 `CHANGELOG.md`，只在 `D:\Tools\LGK-Vector` 的 Git 仓库提交工具改动。
7. 其他 AUTOSAR 工程无需同步文件；下一次调用中央工具时自动获得更新。

## 6. 仓库边界

中央工具仓库保存：Rust 源码、Skill、脚本、测试、公开说明和更新记录。

各 AUTOSAR 工程保存：自己的 `lgk-vector.json`、ECUC 配置、DaVinci 生成输出和业务代码。

不要把客户 DPA/ARXML/DBC、Vector SIP、许可证、原厂文件、反编译产物、账号、Token 或客户生成代码提交到中央工具仓库。
