# LGK-Vector 跨工程接入与源码维护

## 1. 推荐目录

LGK-Vector 的 Skill 和源码放在同一个目录。这样新的 Codex 对话一旦启用 `$lgk-vector`，既能按规则调用程序，也能直接查看 `src`、`scripts` 和 `tests`，发现问题后能在同一套源码上修复。

```text
LGK-Vector/
├─ SKILL.md                 # Codex 工作规则，也是源码入口
├─ agents/openai.yaml       # Skill 显示与默认提示
├─ Cargo.toml / Cargo.lock  # Rust 工程
├─ src/                     # Rust 核心与两个程序入口
├─ scripts/                 # PowerShell 调用器与发布同步脚本
├─ tests/                   # 不依赖客户工程的测试
├─ docs/                    # 使用和接入说明
├─ CHANGELOG.md             # 每次更新的正式记录
└─ lgk-vector*.exe          # 发布包可带；源码仓库通常由 Release 提供
```

## 2. 安装为本机 Skill

把完整源码仓库克隆或复制到当前用户的 Codex skills 目录，并保持目录名为 `lgk-vector`：

```text
C:\Users\<用户名>\.codex\skills\lgk-vector\
```

关键点不是只复制 `SKILL.md`，而是让 `Cargo.toml`、`src`、`scripts`、`tests` 与它同处一个根目录。重新打开任务后可以直接说：

```text
使用 $lgk-vector 查看当前工程的 COM 配置；如果工具自身有问题，先查看 Skill 根目录中的 Rust 源码和 CHANGELOG，再做最小修复。
```

团队也可以把完整目录放进每个 AUTOSAR 仓库的 `Vector/LGK-Vector`。Skill 的查找顺序是：当前 Skill 根目录、当前工程的 `Vector/LGK-Vector`、用户明确给出的路径。

## 3. 给一个新 AUTOSAR 工程配置

在 DaVinci 的 Cfg 目录创建 `lgk-vector.json`：

```json
{
  "project_path": "D:\\Work\\Vehicle\\Proj_Config\\Bsw_Config\\Cfg",
  "tool_path": "D:\\Vector\\SIP"
}
```

`project_path` 必须等于 JSON 所在目录。`tool_path` 指向本机实际 SIP/DaVinci 工具根目录。如果自动发现遇到多个 `.dpa` 或多个 `DVCfgCmd.exe`，再增加：

```json
{
  "project_path": "D:\\Work\\Vehicle\\Proj_Config\\Bsw_Config\\Cfg",
  "tool_path": "D:\\Vector\\SIP",
  "project_file": "D:\\Work\\Vehicle\\Proj_Config\\Bsw_Config\\Cfg\\Vehicle.dpa",
  "davinci_command_path": "D:\\Vector\\DaVinci\\Exec\\DVCfgCmd.exe"
}
```

旧工程使用的 `LGK_project_path`、`LGK_tool_path` 仍兼容；新工程统一用小写字段。

## 4. 调用示例

只读查看 COM Signal，不启动 DaVinci：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\Vehicle\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"inspect_ecuc_containers","module":"Com","container":"ComSignal","short_name_regex":"^VehicleSpeed$","params":["ComBitPosition","ComBitSize"]}'
```

第一次接入可以加 `-ValidateOnly`。它只验证请求、配置路径、工具路径和程序位置，不启动 resident host，也不进入 DaVinci：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\Vehicle\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"find_module","module":"Com"}' `
  -ValidateOnly
```

查询参数定义：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\Vehicle\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"get_param_definition","module":"Com","params":"ComBitPosition"}'
```

会话结束：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\Vehicle\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"shutdown_host"}'
```

`inspect_ecuc_containers`、模块发现、模板和参数查询属于本地只读操作。`get_errors_list`、`auto_solve_errors`、`generate_code` 会进入 DaVinci 会话。ECUC 修改与生成的 C/H/LSL 必须在说明和 Git 差异中分开看待。

## 5. 把新版本同步到工程包

先在源码仓库完成测试和 release 构建，再运行：

```powershell
& ".\scripts\Sync-LGKVectorPackage.ps1" `
  -DestinationRoot "D:\Work\Vehicle\Vector\LGK-Vector" `
  -IncludeBinaries
```

脚本只复制 LGK-Vector 清单内的源码、Skill、说明和可选发布程序，不读取或修改目标工程的 ARXML、生成代码和构建产物。同步后在目标仓库检查 Git 差异，只提交 `Vector/LGK-Vector` 及该工程的工具说明/更新记录。

## 6. 发现问题后的更新流程

1. 在 `CHANGELOG.md` 先确认当前版本和已知限制。
2. 从失败请求中提取最小复现，使用公开、虚构的 ECUC 测试夹具；不要提交客户文件。
3. 查看对应源码：本地操作在 `src/ops`，host/DaVinci 协议在 `src/app` 和 `src/daemon`，调用器在 `scripts`。
4. 修改源码并补一个能失败后转为通过的测试。
5. 运行 `cargo test --all-targets --locked` 和 `cargo build --release --locked`。
6. 先提交功能，再把其提交号写进 `CHANGELOG.md` 并提交文档。
7. 用同步脚本更新需要使用该版本的工程包，并在工程仓库单独提交。

不得将客户 DPA/ARXML/DBC、SIP、许可证、Vector 原厂文件、反编译产物、账号、Token 或生成的客户代码放进开源仓库。
