# DaVinci 5 原生写入实验与跨请求安全撤销设计

日期：2026-10-07。此文区分已验证的只读查询、单 Boolean 原生写入实验和未实现的撤销协议。
LGK 默认已有值修改仍采用 expected 与原文件字节复核；没有切换 DaVinci 写入路径。

## 1. 本机版本的接口依据

本机 DaVinci 5 的官方 WriteTheActiveEcuC 示例说明：bswmdModel 对象可以在 transaction
内创建容器/参数并设置值。样例使用生成的 EcuC 类型，不能据此假定所有 SIP 都有相同类名。
本机 AutomationInterface Javadoc 另外确认以下通用接口：

| 接口 | 文档确认的范围 |
| --- | --- |
| IBswmdModelApiEntryPoint.bswmdModel(Class, String) | 接受 GIXXX 或生成类型；按 IMdfModelApi 的路径规则查询，限制在 ActiveEcuC。 |
| IMdfModelApi.mdfModel(String) | 区分 AUTOSAR 路径、ObjectLink 和 Definition Ref；部分查找可能遍历整个模型，应要求唯一命中。 |
| GIBoolParameter.getValue/setValue | 读取/设置 Boolean；实验只选一个已有叶子，不创建对象。 |
| IProject.getDpaProjectFilePath/saveProject | 可核对当前 DPA 绝对路径并保存工程。 |
| IValidationApi.getValidationResults | 等待后台校验空闲后返回结果，不等于所有生成阶段检查。 |
| IPersistencyModelImportApi.importModuleConfigurations | 可向 ActiveEcuC 导入模块配置；replaceInModel 指定替换，module(String) 参数是 Definition Ref。 |

这些依据来自本机 DaVinci 5 的文档 ZIP 和示例，未把 Vector 示例、Javadoc 或 AutoC 代码
复制进 LGK。模块导入/替换与 transaction 内单值写入是不同路线，必须分别验收。

## 2. 独立实验入口与本次结果

维护者入口是 scripts/Invoke-LGKNativeBooleanProbe.ps1 与
assets/experiments/LGKNativeBooleanProbe.dvgroovy。它们不属于正式请求白名单，
不打包到用户运行时，也没有接入常驻 Daemon。可先使用 PrepareOnly，创建新的隔离副本：

```powershell
& .\scripts\Invoke-LGKNativeBooleanProbe.ps1 `
  -SampleProjectPath '<许可匹配的非客户示例目录>' `
  -ToolPath '<匹配 SIP 根目录>' `
  -WorkRoot '<仓库、SIP、输入示例外的全新目录>' `
  -PrepareOnly
```

去掉 PrepareOnly 后，实验要求唯一 DPA、工程内全部 ECUC/输出/注册引用路径和唯一已配置 Boolean 定义；
拒绝源目录链接和隔离目录祖先链接、已有隔离目录及越界的注册路径。原启动 INI 必须有唯一
明确的 Xmx 设置，仅复制到隔离目录并将它改为 1024 MiB；用
[Equinox 官方启动参数 --launcher.ini](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.isv/reference/misc/runtime-options.html)
选择该副本，不修改 SIP 的启动配置。仍有 120 秒与自有进程 1800 MiB 私有内存保护，
不会因堆上限较小而保证任意工程都能加载。停止时只停止本次创建的独立进程树，保留证据。
原生任务核对 active DPA 与一次性清单，先读旧值，再在事务内写新值、重查、保存并核对磁盘，
最后恢复旧值并再核对模型与磁盘。记录校验错误计数及文件前后哈希。恢复原值不保证
Vector 保存时所有其他字节都保持不变；后续必须检查完整文件变化，不能据此提供生产撤销。

第一次尝试使用 SIP 自带 StartApplication 的隔离副本，保存在仓库外的
ReverseEngineering/lgk-native-probe-20261007-1。未使用客户 ECUC。DaVinci 进入
Loading AUTOSAR XML files 阶段后，自有进程私有内存达到接近 2 GiB 的保护阈值，
驱动停止该进程树并保留日志；清单仍为 prepared，事务写入脚本没有开始。
这证明了本次尝试受资源保护中止，**不能证明 Boolean 原生读、写、保存、恢复成功**。
后续查明本机原 INI 的 Xmx 为 16384 MiB；原设置可能促成高内存占用，但首次中止不能单独证明因果。

日志同时显示 DaVinci 首次生成了 SIP 的 Automation BswmdModel 缓存。
该厂商自动缓存位于 SIP，未进入 LGK 仓库；运行实验需将这种初始化副作用纳入准备。

第二次以独立 1024 MiB 堆配置加载新的副本，成功完成同一个已有 Boolean 的事务修改、
模型重查、保存和恢复。随后为完整文件复核补充实验记录，在第三个新副本验证最终脚本。
保护阈值保持不变，没有绕过许可证、操作客户 ECUC 或执行生成。最终证据保存在仓库外的
ReverseEngineering/lgk-native-probe-20261007-3/native-evidence.json，原始日志和文件基线一并保留。

| 最终实验观察 | 结果与限制 |
| --- | --- |
| 原生模型与磁盘 Boolean | false → true → false，模型重查和两次保存后磁盘核对均通过。 |
| 目标 Com 文件 | 写后哈希变化，恢复后 SHA-256 与事务前一致；仅证明此目标文件恢复。 |
| 校验 ERROR 数 | 前、写后、恢复后均 254；工程有既有错误，计数相同不证明消息集合相同或全部校验通过。 |
| 复制输入的完整文件复核 | 506 个文件以启动前哈希复核；DPA、Os 文件发生变化，没有新增 DPA/ARXML。 |
| 原输入与原启动配置 | 506 个源文件及 SIP INI 的运行前后哈希一致。 |
| 运行资源 | 最终运行约 19 秒，观测的自有进程私有内存峰值约 1744 MiB；不是跨工程性能基准。 |

Os 差异包含厂商派生信息，DPA 差异包含工程设置。它们是在加载/保存后的副本变化，
没有分阶段证据可把全部变化归因于 Boolean 事务。**单叶值恢复不等于整工程撤销**，
原生路径仍仅维护者实验入口；没有正式 native 写请求、结构创建、模块替换或映射写入验收，
更没有修改默认 Daemon 路径。生产接入前须确认实际保存集、校验变化与同步/撤销策略。

本轮 synthetic onboarding 覆盖 PrepareOnly 不启动 DaVinci、旧值/候选值清单、输入字节
保持不变、已有目录保留、受保护目录与全部注册路径拒绝、私有 INI 仅改堆参数，以及
缺失明确堆上限时在复制前拒绝。包检查要求两个实验脚本不进入发布包。
这些合成检查和上述真实单 Boolean 验收分别记录，不将它们扩大为完整原生工作流验收。

## 3. 安全撤销的最小协议草案（未实现）

第一版只支持一个已有 ECUC 值或一个已有 ASW 引用。生成、自动求解、Project Update、
DBC 导入、结构创建及模块导入暂不纳入。建议接口 list_changes、preview_undo、undo_change
均为设计名称，目前不可调用。

持久记录必须在仓库与客户配置目录之外的用户状态目录，不存到发布包；不得记录许可证
或认证 Token。以规范化工程目录、DPA 路径和 SIP 身份形成工程键，不能按显示名称找工程。

| 字段 | 要求 |
| --- | --- |
| schema、operation_id、tool_build | 明确格式版本，随机不可复用 ID，记录实际工具构建。 |
| project_identity、dpa_fingerprint、definition_identity | 规范化路径和 DPA/相关定义的内容指纹；跨工程或更新定义时拒绝自动恢复。 |
| operation_kind、semantic_target | 固定允许类型；记录 module/container/definition 或 object/kind/role，不能从日志执行任意函数。 |
| old_value、new_value | 完整语义值；不能使用响应中截断后的旧值作为逆操作依据。 |
| relative_file、before_sha256、after_sha256 | 用文件内容复核；时间戳仅作提示，不能作为通过依据。 |
| old_span_bytes、new_span_bytes、span_location | 保存已验证变更区域的原始字节，以恢复 XML 转义、换行等表示；限定尺寸，不默认备份整个工程。 |
| state、validation_receipt、native_sync_state | 区分 prepared/applied/undo_prepared/undone/uncertain；模型同步状态未知时禁止自动撤销。 |

必须先形成并持久化 prepared 记录，再对原文件执行现有 replace_checked，最后标记 applied。
日志更新失败不能包装成正常成功。文件与日志不是一个断电原子事务；重启遇到未完成记录
时，用 before/after 哈希识别未应用、已应用或外部变化，后者进入 uncertain 并要求核查。
不能仅因为上次请求异常而假定文件未改。

## 4. 撤销前必须全部通过的复核

1. 获取工程级写锁；日志目标的规范化路径必须仍在同一工程，拒绝 reparse point 越界和未知 schema。
2. 核对工程/DPA/相关定义身份、日志状态 applied；不能跨工程选择同名对象。
3. 重新语义定位唯一目标，当前完整值必须等于记录的新值。
4. 整个当前文件 SHA-256 必须等于写后哈希。即使目标值未变，外部修改其他段落也拒绝自动覆盖。
5. 在内存中按受约束字节跨度恢复旧值；复解析 XML、重定位目标并核对旧值，以及候选文件与写前哈希一致。
6. 持久化 undo_prepared，然后用 replace_checked 再复核原字节并原子替换；重新读取磁盘，确认恢复哈希再标记 undone。

任何失败保持当前配置，不提供 force 覆盖开关。拒绝的结果应包含紧凑错误码，例如
UNDO_PROJECT_MISMATCH、UNDO_VALUE_CHANGED、UNDO_FILE_CHANGED、UNDO_RECORD_UNCERTAIN，
只返回必要目标和状态。重复撤销报告 already_undone，不再次写文件。
关闭 Host 后仍可读取同一用户状态记录；不要把“同请求内失败回滚”称为跨请求撤销。

多次变更同一文件时，先撤销较新的操作；其精确恢复后，较旧操作的写后哈希才能重新匹配。
未来跨文件操作须整组预检、逐文件状态记录、失败时只恢复仍匹配本次写后内容的文件；
不得循环调用单项撤销后声称整组原子恢复。用户 GUI 始终须先保存关闭；工程锁不能锁住
不合作的外部应用，现有原字节复核和失败报告仍是必要边界。

## 5. 与 DaVinci 原生模型结合时的附加条件

原生修改需要记录旧/新模型值、内存重查、保存后的文件变化及校验证据。
只能把磁盘和内存均已确认的状态标记为可撤销；保存异常、进程退出或脚本 timeout 后，
不能只反向写磁盘再宣称模型已恢复。先关闭本工具拥有的 DaVinci 会话，对磁盘复核并恢复，
再在可控工程重开模型、重查和校验；任一步不确定都停止。GUI 保存可能覆盖外部修改，
因此沿用关闭同一 GUI 工程的前提。

模块导入可能触发跨模块引用或供应商保存副作用，不能按一个参数的逆操作处理。
在模块导入、校验、保存和完整文件差异没有可丢弃工程验收前，不扩大撤销范围。

## 6. 必须补齐的验收矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 单值跨请求写入、关闭 Host、重开后撤销 | 日志可找回；旧语义值及原始文件字节恢复。 |
| 当前目标被外部修改 | UNDO_VALUE_CHANGED，无文件变化。 |
| 目标未变但文件其他部分改变 | UNDO_FILE_CHANGED，无覆盖。 |
| 同名目标在另一工程、DPA/定义更新、路径变为链接 | 身份/边界拒绝，不触及外部文件。 |
| XML 转义、Unicode、CRLF、注释同名文本 | 精确目标及原字节恢复；未知扩展保持不变。 |
| prepared 后、文件替换后、undone 落盘前中断 | 根据哈希分类恢复状态；不能猜测成功或反复应用。 |
| 多次修改同一文件和重复撤销 | 先撤较新项；重复请求无写入。 |
| 日志损坏、跨度过大、磁盘满、恢复阶段写失败 | 拒绝或明确 uncertain；保留可核查记录。 |

现有 Rust 测试已覆盖 expected 过期、目标歧义、注释、文件替换前变化和组写失败尽力回滚；
这些是可复用的基础，不代表上表的持久日志、重启恢复或跨请求撤销已经通过。
