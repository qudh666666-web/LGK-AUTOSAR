# CAN 控制器切换说明（面向工程人员）

## 这份说明解决什么问题

当需求说“把 CAN1 改为 CAN0”（或反过来）时，不能只改 DaVinci 里
`Can` 模块的一个控制器编号。CAN 报文能否真正发到总线上，取决于从应用
软件到 MCU 引脚、收发器和线束的一整条链路；其中任何一个环节仍指向旧通道，
工程都可能正常生成、正常编译，却没有一帧报文。

本说明是给工程人员阅读的中文版本。LGK-Vector 的 `SKILL.md` 保留英文规则，
供 Agent 执行时使用。

## 先确认硬件：CAN0 和 CAN1 不等于同一组引脚

开始改配置前，先从原理图或引脚表记录目标网络的以下信息：

- 使用的 MCU CAN 控制器：CAN0 还是 CAN1；
- 该控制器实际连接的 RX、TX 引脚；
- 对应的 CAN 收发器型号；
- 收发器的使能、待机（EN/STB/NEN）DIO 引脚；
- CANH、CANL 从哪个连接器引出，以及终端电阻在哪里。

MCU 有 CAN1 功能，并不代表板上一定装有 CAN1 收发器。若板上只有 CAN0 的
收发器和 CANH/CANL 接口，把软件改为 CAN1 后通常会导致总线静默。

## 修改时要一起看的配置

把 CAN1 切到 CAN0 时，以下内容是一组原子修改项；不要只完成其中一项就生成
或下结论。

1. **Can 模块**：目标网络应绑定到 CAN0 对应的控制器节点、RX/TX 引脚选择和
   中断配置。
2. **CanTrcv 模块**：收发器必须是物理上接到 CAN0 的那一颗；同时确认它的
   RX、TX、使能/待机 DIO 引用。驱动仍能编译不代表收发器接对了控制器。
3. **EcuC、EcuM、BswM、CanIf 与 RTE**：搜索旧收发器或旧网络的符号，只修改
   确认仍然指向旧通道的引用、初始化项、回调和映射。
4. **发送 PDU 链路**：每一个需要发送的 Tx PDU 都要落在目标 CanIf 控制器和
   目标 Can Hardware Object 上；生成文件中的配置表或注释应能对应到目标网络。
5. **通信状态**：启动阶段的 BswM/ComM 必须对目标主网络请求
   `Full Communication`。只有 `CommunicationAllowed` 往往还不足以让应用报文
   真正发送。
6. **构建输入**：如果收发器实现也换了，检查驱动头文件、源文件、构建输入和
   生成的 callout，不能残留旧收发器实现名。

## 推荐操作顺序

1. 先用 LGK-Vector 只读查看 `Can`、`CanTrcv` 的实际容器和参数，不凭名称猜测。
2. 在 DaVinci GUI 中保存并关闭项目，避免 GUI 内存里的旧模型覆盖外部 ARXML。
3. 以很小的范围修改 ECUC；每次修改应带有“修改前文本完全一致”的检查条件。
4. 先生成 `CanTrcv`，再只生成确实受到影响的集成模块。除非明确需要，不进行
   全工程生成。
5. 阅读最新的 DaVinci Generation Report。只有“校验 0 error”、目标模块的
   `GENERATION` 阶段成功，才算生成成功。
6. 编译后确认实际使用的是本次构建产生的 HEX/ELF，而不是旧的 Debug 文件。

## 为什么“编译成功”仍可能没有报文

编译和链接只说明软件符号能拼起来，不能证明总线上有信号。出现“零报文”时，
按下面顺序检查，不要继续盲目修改 ECUC：

1. 从最新 HEX/ELF 的位置确认真正构建的是哪一个工程根目录。
2. 查看 map 文件：应有目标 CAN 控制器 ISR 和目标收发器符号，不应残留旧收发器
   的符号。
3. 追一条 Tx PDU：应用 runnable → `Rte_Write` 或 `Com_SendSignal` →
   `Com_MainFunctionTx` → `CanIf_Transmit` → 生成的 Can Tx PDU。确认 runnable、
   触发方式和发送任务都在运行。
4. 在线确认控制器状态为 `STARTED`、收发器状态为 `NORMAL`，并确认 BswM/NM
   当前状态允许该网络通信。
5. 测试工具的波特率必须与配置一致，测试线必须接在目标收发器的 CANH/CANL 上。
   CAN1 改 CAN0 后，线束、终端电阻和使能引脚也可能必须跟着换。
6. 重新刷写刚刚生成的 HEX/ELF，并核对下载日志中的文件名和时间。

若以上软件检查都通过仍无报文，优先收集硬件证据：CANH/CANL 路由、终端电阻、
收发器供电与使能、总线波特率，以及是否有其他节点 ACK。此时不应继续反复改
DaVinci 配置。

## 最常见的误区

- 只改了 `Can`，没有改实际收发器或其 DIO 引脚；
- 把 CAN0 控制器与 CAN1 的收发器/引脚组合在一起；
- 只看到 ELF 链接成功，就认为 CAN 已经发送；
- 修改了 ARXML 后仍使用旧的 DaVinci 会话或旧的生成报告；
- 本次编译成功，但下载了之前生成的 HEX；
- 直接手改生成的 C/H 文件。正确顺序是先修 ECUC，再进行针对性生成。

## 完成标准

满足以下三类证据，才可以说 CAN1 → CAN0 切换完成：

- **配置证据**：ECUC 及最新生成报告均无错误，目标控制器、收发器、PDU 和通信
  状态都已指向 CAN0；
- **构建证据**：最新 HEX/ELF、map 和下载日志对应同一次构建；
- **实车/台架证据**：在正确的 CANH/CANL、波特率和终端条件下，能观察到目标报文，
  并有其他节点正常 ACK。
